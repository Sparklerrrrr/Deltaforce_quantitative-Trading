## 1. 方法

| 方法 | 工具 | 说明 |
|---|---|---|
| 源码扫描 | `python scripts/scan_secrets.py --tree` | 扫描 `git ls-files` 列出的每个文件 |
| Git 历史扫描 | `python scripts/scan_secrets.py --history` | `git rev-list --all --objects` 列出所有引用可达的对象，再用 `git cat-file --batch` 逐个读出文件内容；同一个文件版本只扫一次；另外统计提交作者 / 提交者邮箱 |
| 打包目录 / 安装目录扫描 | `python scripts/scan_secrets.py --dir <目录>` | 扫描文件内容，并**按文件名**找不该出现的个人文件（`.env`、`config.yaml`、`data/`、`*.db`、日志、邮件、浏览器登录数据、私钥文件等）；个人文件只报告名字、不读内容 |
| 代码审查 | 人工 | 首次启动、`.env` 读取、打包入口、安装 / 卸载脚本、计划任务 |
| 自动测试 | pytest | 见第 6 节 |

`scan_secrets.py` 的规则覆盖：私钥块（RSA / EC / OPENSSH / PGP）、`sk-` 类 API Key、Tavily Key、GitHub token、AWS Access Key、Google API Key、Slack token、JWT、数据库连接串里的密码、Cookie / Session（含 B 站 `SESSDATA` 等）、`Authorization` 头、`*_TOKEN / *_PASSWORD / *_SECRET / *_API_KEY` 赋值、邮箱授权码形状、邮箱地址、本机用户目录路径。

每个命中分成四类，只有“疑似真实”会让扫描失败（退出码 1）：

| 分类 | 含义 |
|---|---|
| 疑似真实 | 形状像真密钥 / 真邮箱 / 真用户名，又没有任何“假值”标记 |
| 占位符 | `<你的token>`、`your-token`、`${VAR}` 这类写法 |
| 测试假值 | 带 `dummy` / `test` / `example` 等字样，或测试里由单词拼成的可读值 |
| 误报 | 变量名、表达式、保留域名（`example.com`）等 |

确认无害、但规则认不出来的命中登记在 `scripts/scan_allowlist.txt`（钉在具体值的指纹上、写明理由），不在代码里开后门。

局限：按“形状”找密钥，认不出既没有固定前缀、又没写在 `xxx_token = ...` 位置的密钥；二进制文件只查前缀明确的几类；PyInstaller 压缩归档内部不展开（打包内容来自已扫描过的源码，所以发布要求从干净的检出构建）。
