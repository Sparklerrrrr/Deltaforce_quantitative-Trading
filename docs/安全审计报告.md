## 4. .gitignore 说明

完整内容见仓库根目录的 `.gitignore`（中文注释），按 7 类组织：

1. **密钥与凭据**：`.env` 及所有变体（`.env.*`、`*.env`），只放行 `.env.example`；证书与私钥（`*.pem`、`*.key`、`*.pfx` 等）；浏览器登录状态目录。
2. **用户配置**：根目录的 `config.yaml`、`config.local.yaml`（模板 `config.example.yaml` 不受影响）。
3. **运行时数据**：整个 `/data/`，以及任何位置的数据库、日志、邮件文件；旧版本写在 `docs/` 下的接口实测报告；`manual_notes/` 里的原文（只放行说明文件）。
4. **Python 运行与测试**：`__pycache__`、`*.pyc`、虚拟环境、各类测试 / 类型检查 / 覆盖率缓存。
5. **构建产物与安装包**：`/build/`、`/dist/`、`*.spec`、`*.exe`、根目录的 `/_internal/`。
6. **编辑器与系统杂项**：`.vscode/`、`.idea/`、`Thumbs.db`、`Desktop.ini` 等。
7. **本地参考资料**：`三角洲/`。

验证：用 `git check-ignore -v` 逐项确认了 20 类应忽略的路径全部命中规则、12 个必须保留的文件全部不被忽略；`git ls-files -ci --exclude-standard` 为空，即**没有任何已跟踪文件需要移出版本控制**。

## 5. 安全审计结果

| # | 问题 | 等级 | 处理 |
|---|---|---|---|
| 1 | **页面可以间接读到密钥。** pywebview 会递归暴露 `js_api` 对象的公开属性，`Api.store`（密钥存储）因此对页面可见；且它按点号路径取属性时不拦截下划线名字。页面若被注入脚本，可调用 `store.backend.read(...)` 读出明文密钥。 | 中危 | 改为只暴露一个“门面”对象：仅白名单里的方法、没有任何属性，转发函数按原签名生成且不留 `__wrapped__`；并为页面加上 CSP（禁止任何网络连接、禁止内联脚本），即使被注入也无法外传。新增 13 个测试覆盖各条可疑路径。 |
| 2 | **卸载时可能误删交易记录。** 原先除“完全删除”外，其余选项也会删除 `data/`（含交易数据库）。 | 中危 | 卸载改为三档：默认“保留配置和交易数据、删除密钥”；“再保留密钥”；“完全删除”。保留清单与 `dfq/layout.py` 一致并有测试比对。 |
| 3 | **卸载递归删除会跟随目录联接。** 用 Inno 的 `DelTree` 删除，遇到符号链接 / 目录联接可能删到安装目录之外。 | 中危 | 改为自写的 `SafeDelete`：遇到链接只删链接本身。实测：在 `data/cache` 放一个指向外部目录的联接，“完全删除”后外部文件完好。 |
| 4 | **计划任务脚本在 Windows PowerShell 5.1 下运行失败。** 双引号字符串里的中文弯引号“”被当成引号，把字符串截断，任务没有创建（语法检查却能通过）。 | 中危（功能性） | 全部改为「」；新增测试禁止 `.ps1` 中出现弯引号。实测任务正确创建、指向安装目录的 `DFQ.exe`、卸载时被删除。 |
| 5 | **配置导入可被“压缩炸弹”拖垮。** 大小检查依赖 zip 头里可伪造的声明值。 | 低危 | 改为边解压边计数，超过 1 MB 立即停止；新增测试。 |
| 6 | **两个不同目录的 DFQ 同时运行时互相串页面。** pywebview 自带网页服务在非无痕模式下固定用 42001 端口，后启动的会显示先启动那个的页面，并在本机开放一个端口。 | 低危 | 改为 `file://` 直接加载本地页面，不再启动网页服务、不再监听端口。 |
| 7 | **接口实测报告写进源码目录 `docs/`**，可能被误提交（含真实价格数据）。 | 低危 | 改写到 `data/reports/`；旧文件已被 `.gitignore` 忽略并保留在原处。 |
| 8 | **构建工具版本不固定**（`pyinstaller>=6.16`），每次构建可能拉到不同版本。 | 低危 | 固定为 `pyinstaller==6.22.3`。 |
| 9 | **开发环境 pip 26.1.1 有 4 个已知漏洞**（GHSA-qwm4-qh6w-59xr、GHSA-wf93-45jw-7689 等）。 | 低危（只在开发机） | 升级到 26.3（无已知漏洞）；确认 pip 未被打进程序。 |
| 10 | **升级时程序仍在运行**可能导致文件只替换一半。 | 低危 | 程序持有具名互斥体，安装 / 卸载程序（`AppMutex`）检测到时提示先退出。 |
| 11 | 单实例命名管道的认证密钥由安装路径推导，同一用户的其他进程可以伪造“显示窗口”指令。 | 建议 | 指令只有“显示窗口”一种，无害；管道默认权限不允许其他 Windows 用户写入。保持现状。 |
| 12 | `dfq mail-poll` 在邮件未开启时以返回码 1 结束，计划任务会显示“上次运行失败”。 | 建议 | 不影响安全和数据；可改为“未开启则跳过”，留待后续。 |
| 13 | `.env` 为明文存储，文件权限继承安装目录。 | 建议 | 这是 dotenv 方案的固有性质；防的是误提交 / 误上传，不防本机恶意程序。已在 README 与卸载界面说明。 |

### 5.1 复核后确认没有问题的方面

- **命令执行**：全部 4 处外部调用（记事本、资源管理器、PowerShell 计划任务脚本、打开文件夹）都以参数列表调用固定程序，没有 shell 字符串拼接，不存在命令注入。
- **网络**：大模型与小涛查只允许 `https://`（本机回环地址需显式开启才允许 `http`）；不跟随重定向（防止密钥被转发到别的主机）；所有请求有超时和有限重试；邮件 465 端口用 SSL，其他端口先 `STARTTLS` 再登录，使用标准证书校验。
- **日志与缓存**：所有日志经过脱敏；接口缓存不保存 token。实测扫描未发现泄漏。
- **路径**：页面能打开的文件夹是固定白名单；导入只读取压缩包里固定名字的两个文件，不会解压到任意路径。
- **安装程序**：最低权限运行（不需要管理员）；拒绝安装到盘符根目录、Program Files、Windows 目录和用户主目录；目录里已有其他文件时提醒；卸载时再次校验目录，绝不清空危险位置。
- **依赖**：14 个运行与构建依赖经 OSV 漏洞库核对，均无已知漏洞。

### 5.2 未解决 / 剩余风险

- 密钥目前为空，需要你重新填写（见 1.3）。
- `.env` 明文存储的固有风险（见第 13 项）。
