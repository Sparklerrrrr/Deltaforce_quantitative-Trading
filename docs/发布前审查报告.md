## 逐项结论

格式：是否存在 ／ 代码位置（修复前）／ 风险 ／ 修复方案 ／ 是否已修复 ／ 对应测试。

### 1. 卖出数量超过持仓仍然记账（P1）
- **存在**。`dfq/ledger.py` 的 `record_trade` 超卖时只在备注里加一句，照样写入；`positions()` 把超卖部分的卖出款全部算成利润；`delete_trade` 可以删掉后面卖出所依赖的买入。
- 修复：卖出按**同一本账**（真实 / 模拟分开）的时间线校验，任何时刻持仓都不能为负，否则拒绝、一行不写，并告诉用户怎么办；撤销买入前检查依赖；新增独立的**期初库存**（`dfq inventory add 品种 数量 成本单价`，计入持仓和成本、不动余额，成本必须为正）；旧版本留下的超卖记录不再算利润，`dfq status` / `dfq balance` 里逐条提示。卖出可填实际到手金额 `--net`。
- **已修复**。测试：`tests/test_ledger_integrity.py`（46 个，包括 `test_oversell_is_rejected_and_nothing_is_written`、`test_backdated_sell_is_checked_against_the_timeline`、`test_legacy_oversell_is_not_profit_and_is_reported`）、`test_paper_isolation.py::test_oversell_check_uses_the_same_book`（原来断言“超卖也记账”，属于把 bug 当正确行为，已改为断言拒绝）。

### 2. 账本缺少原子性保护（P1）
- **存在**。`record_trade` 先 `positions()` 查持仓、再 `INSERT`，中间没有事务；界面、计划任务、命令行是不同进程，可以同时通过检查。
- 修复：新增 `DB.write_tx()`（`BEGIN IMMEDIATE`，一开始就拿写锁，可嵌套，任何一层失败整体回滚、即使异常被吞掉也不提交）。记账、撤销、期初库存、设余额的“检查 + 写入”都在一个写事务里；拿不到锁返回“数据库正被另一个 DFQ 进程占用”（命令行退出码 3），被拒绝的退出码 2。
- **已修复**。测试：`tests/test_db_tx.py`（6 个）、`test_two_processes_selling_everything_at_once_exactly_one_wins`（两个进程同时卖光，恰好一个成功）、`test_random_operations_keep_funds_consistent`（随机操作序列，每一步检查：持仓不为负、余额恒等式成立、失败的操作前后余额 / 持仓 / 成交数 / 已实现盈亏完全不变）。

### 3. 13% 手续费缺少真实数据验证（P2）
- **存在**。13% 只来自最初给定的数字和文档里的一个例子；而且旧代码用“秒出价”反推费率（`features.fee_check`），真实数据里秒出价只比现价低 1%～4%，它其实是“想立刻卖出时建议的挂单价”，不是扣费后到手价——所以每份计划里那条“反推费率约 1.4%，与 13% 相差较大”的提示是误报。
- 核实：2026-11-16 用真实接口 `exchange_pay`（1 次额度）查了 9 种子弹，平台算出的手续费 `sxf ÷ priceMax` 全部在 **12.998%～13.000%**，与等级、单价无关。注意这是第三方平台（小涛查）的口径，不是游戏官方公告；5 级子弹不在该接口范围内（外推）。
- 修复：`fees.sell_fee_rate` 仍默认 0.13，新增按品种覆盖 `fees.overrides`；规则、护栏、复盘、持仓估值都按品种取费率；`dfq fee-check` 调一次平台接口核对并存档；卖出时填实际到手金额后可按真实成交校准；计划里明确写出费率依据（“已用平台数据核对 / 按你的实际成交校准 / 未核对：13% 是默认值”）。删除了秒出价误报，改成中性的“秒出通常要让价约 x%”。
- **已修复**。测试：`tests/test_fee_check.py`（18 个）、`test_rules_features.py::test_fee_check_no_longer_treats_quick_sell_price_as_fee`。

### 4. 止损缺少资金损失约束（P2）
- **存在**。原来只有每日投入、单品种、总仓位三个上限和最小数量；没有单笔亏损上限、持仓时间限制、累计亏损 / 连续亏损暂停、异常波动保护。
- 修复（新文件 `dfq/risk.py`，全部在护栏里、模型输出之后执行）：
  - 单笔买入如果打到止损线的实际亏损（含卖出费）超过总资产的 `risk.max_loss_per_trade_pct`（默认 3%）→ 削减数量，削到不足最小数量就改观望；
  - 持仓超过 `risk.max_holding_days`（默认 7 天）→ 卖出线降到回本价；超过两倍 → 建议按现价卖出（时间止损）；
  - 近 `risk.loss_window_days`（30 天）已实现亏损超过资金基准的 `risk.max_cumulative_loss_pct`（10%），或连续 `risk.halt_after_losses`（3）笔亏损 → **暂停新的买入**，直到你运行 `dfq risk resume` 确认；
  - 今日涨跌或偏离 7 日中位价超过 `risk.abnormal_move_pct`（12%）→ 当天不买。
  - 真实账本、模拟账本、模拟数据各算各的。
- **已修复**（判定规则的取舍见“待你决定”）。测试：`tests/test_risk.py`（33 个，包括模型试图放大数量、抬高买入价、把暂停的品种改成买入，最终计划都不越界）。

### 5. 量化策略缺少真实成交验证（P2）
- **存在**。`perf` / 复盘只统计“之后的行情有没有碰到计划价”（理论触线），而且在邮件里叫“模拟盈亏”；没有任何地方统计真实成交率、滑点、资金占用。
- 修复：新增 `dfq exec-stats [--days N] [--paper]`（`dfq/execstats.py`）：只用你的成交账本和建议记录，统计建议成交率（写出分子分母，和理论触线率对比）、买卖滑点、先进先出配对的持有时间和资金占用、已实现盈亏；期初库存不计入；账本为空时直说“无法统计”。理论触线统计改称“理论盈亏（理论触线统计）”，`--mock` 输出一律标“【模拟数据】人为生成的行情，只用于演示，不能说明策略是否赚钱”。策略失效检测见第 4 条（连续亏损暂停）。
- **已修复**。测试：`tests/test_execstats.py`（11 个）。

### 6. 邮件身份验证边界（P1）
- **存在**，而且比评审说的更多（以下全部写脚本复现过）：
  - `dmarc=pass` 不带 `header.from` 也放行；`header.from=evil.com@example.com`、多个 `@`、同一属性写两次取最后一个，都能骗过域名比对；
  - 解析器不认识引号字符串和注释，发件人可控的值里塞一段 `; dkim=pass` 或一个左括号就能伪造或吞掉后面的结论；服务商自己的头写法稍有不同（`id/1`）就被跳过、转而采信下面伪造的那条；超长属性名让解析耗时平方增长（10 万字符 6.5 秒）；
  - From 头把主人的地址写进显示名就能骗过发件人比对；
  - 同一封回复换个 Message-ID 重发会记两遍；Message-ID 大小写不同算两封；一年前的计划邮件现在回复仍然记账；记到一半崩溃后重跑重复记账；两个轮询同时跑重复记账；`Date` 头（可以写 2099 年）被直接当成交时间；一封畸形邮件让整批轮询失败。
- 修复：按 RFC 8601 严格解析，失败即拒绝；只采信最上面那条受信任的头；DMARC 必须带 `header.from` 且与你的邮箱域完全相等；From 必须恰好一个地址且等于主人地址；回复必须对应一封 `mail.reply_max_age_days`（默认 3 天）内的计划邮件；Message-ID 规范化；“认领邮件 + 写入全部成交”在同一个写事务里，整封全记或全不记；时间只在合理区间内采用；畸形邮件逐封隔离、只记录一次；验证失败不自动回信（保持原样）。
- **已修复**。测试：`tests/test_mail_hardening.py`、`tests/test_mail_auth.py`。
- 局限（如实写明）：用共享域名邮箱（如 qq.com）时，同域其他用户、以及“服务商没写验证结果也没删掉伪造的那条”这两种情况，单靠验证头无法完全排除；所以叠加了“必须回复未过期的计划邮件（Message-ID 不可预测）”和“超卖一律拒绝”两道防线。

### 7. 外部接口和大模型（P2）
- 逐项结论：
  1. 密钥泄露：小涛查的 token 按接口要求放在 URL 参数里，大模型和 Tavily 的 Key 在请求头里。**部分存在**：URL 编码后的 token 没被打码、错误信息先截断后打码可能漏出半截、日志里的异常对象和堆栈没打码、探测报告原样落盘 → 已修。
  2. 重定向：本来就不跟随（已有测试复核）；**新发现**本机 http 模型请求会走系统代理、代理能看到明文 Key → 改为直连。
  3. 超时和重试：合理（15/120/30 秒，只对网络错误和 5xx/429 指数退避）；**存在**：断网时每个接口重试 3 次、每次都计入额度（一晚最多白扣 63 次）→ 加熔断（连续两个接口网络失败就停），加 16 MB 响应上限。
  4. 提示词注入：资讯、新闻本来就隔离和筛查；模型只能收紧规则线、数量由护栏重算。补了：品种名清洗、模型建议的下次运行时间限制在两周内、新闻来源只取主机名。
  5. 异常降级：节点失败本来会降级；**存在**：接口返回垃圾数据（列表 / 字符串 / NaN / 负价）会让解析器崩溃 → 一律当空数据处理。
  6. 绕过风控的路径：**没有**（护栏不通过就不写计划）；加固：执行器拒绝过期计划和非法数量 / 价格。
- **已修复**。测试：`tests/test_external_audit.py`、`test_secure_transport.py`、`test_redact.py`、`test_llm.py`。
